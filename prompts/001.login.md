Heading   The door of TPR — Telegram login, Battle Log shell
Intent    One page a stranger can open, log into, and trust
Role      Base44 builds it · this branch keeps it · VPS serves it
Output    Login that verifies, a log that holds zero lies

▛// telos
TelePromptR is OpenRouter for Telegram: one bot, many agents,
and every relayed message accounted for like a battle report.
This is the app its operator opens all day. I am building it
piece by piece; this prompt is piece one and ONLY piece one.
:: ∎

▛/// law — read before building
- NO sample, demo, placeholder, or example data. Anywhere.
  Every list, card, and total starts EMPTY and says so.
  ∅ is not 0: "no events yet" is honest, a zero pretending
  to be data is a lie. An app that ships with fake relays is
  worthless to me.
- Telegram is the ONLY identity. No passwords, no email, no
  Google, no signup form. Nothing else even appears.
- Never log, print, or echo the bot token or raw initData.
- Do not build pages beyond the two states in this prompt.
:: ∎

▛//▞ design direction
Dark war-room ledger. Reference feel: the Risk Battle Log — baseline image at
Marduk/station/tpr/battle-log.png (kept out of this repo).
- page background: deep slate #10141C, near-black, calm
- cards: #1A2029, rounded, 1px border #262D3A, no glow
- primary text: #EDF1F7 · secondary: #8B94A8
- accent: ledger gold #F2C14E — names, live counts, active
  states. Sparing. It marks what matters, never decoration.
- delivered green #58D6A9 · refused red #E4574F
- typography: clean sans, large confident numbers, generous
  whitespace. Numbers carry the color; prose stays quiet.
The feel is a battle report, not a dashboard. Mobile first —
this lives inside Telegram on a phone.
:: ∎

▛//▞ state one — the door (opened outside a login)
On load, read window.Telegram.WebApp.initData and POST it to
a backend function named auth. While it checks: one quiet
line, "checking signature". No spinner circus.
If there is no initData (opened in a plain browser): ONE
card, centered — "TelePromptR opens from Telegram" and a
single gold button linking to https://t.me/tpr_zenbot.
Nothing else on that screen.
:: ∎

▛//▞ state two — the shell (signed in, nothing yet)
Exactly three zones, same bones as the reference:
- TOP BAR · two running totals, right-aligned: "relayed 0"
  and "spent 0". Real counts later; today they read 0 and
  that is the truth.
- LEFT · THE SHAPE · label: value rows, top to bottom:
  name · telegram id · signed in (time) · bot @tpr_zenbot.
  A copy button on the id, like a Game ID.
- RIGHT · RELAY LOG · panel titled "Relay Log", holding one
  empty state: "No relays yet. Add TPR to a group and speak."
  No fake cards, no grayed examples, no chart at zero.
Log out sits small at the bottom of THE SHAPE.
:: ∎

▛//▞ the auth function — server side, exact
1. Parse initData as a querystring. Extract `hash`.
2. data_check_string = every remaining field as k=v, sorted
   by key, joined with newline.
3. secret = HMAC_SHA256(key="WebAppData",
   msg = TELEGRAM_BOT_TOKEN from project secrets).
4. expected = hex HMAC_SHA256(key=secret,
   msg=data_check_string).
5. Constant-time compare against `hash`. Mismatch = reject.
6. Reject if auth_date is absent, older than 3600s, or in
   the future. Reject if no user field.
7. On success: upsert User by telegram_id, start a session,
   return who. On reject: return the plain reason, log
   nothing sensitive.
:: ∎

▛//▞ data model
User: telegram_id (unique) · username · first_name ·
last_seen. That is all. No other entity exists yet.
:: ∎

- Empty states are designed, honest, and name the next act.

:: ∎
