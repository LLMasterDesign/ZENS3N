# TPR.001 , the login

> Piece one of TelePromptR and ONLY piece one. TPR relays a
> room's messages to agents and accounts for every one.
> Its verb rail is HIRO; the four bindings are Lucius's to
> declare and stand EMPTY above until he does. This prompt
> builds the door and the empty shell of the account.
> Secret required in Base44 project secrets:
> TELEGRAM_BOT_TOKEN. It is never written anywhere else.

## the law

▛/// what may never happen, before what must
- no sample, demo, or placeholder data. Every list, card,
  and total starts EMPTY and says so. "No relays yet" is
  honest; a zero pretending to be data is a lie.
- Telegram is the ONLY identity. No passwords, no email, no
  social logins. Nothing else appears on any screen.
- the bot token and raw initData are never logged or echoed.
- nothing is built beyond the two states below.
yields: an app a stranger can trust on first open.
:: ∎

## state one , the door

▛//▞ opened before any login
Reads window.Telegram.WebApp.initData on load and POSTs it
to the backend function auth. While checking: one quiet line
"checking signature". No initData (plain browser): ONE
centered card, "TelePromptR opens from Telegram", a single
gold button to https://t.me/tpr_zenbot, nothing else.
yields: a door that only Telegram can open.
:: ∎

## state two , the shell

▛//▞ signed in, nothing relayed yet
Three zones, same bones as the baseline:
- TOP: totals right-aligned, "relayed 0" and "spent 0" ,
  true counts, zero today because zero is the truth
- LEFT , the shape: label rows , name · telegram id (with a
  copy button, like a Game ID) · signed in · bot @tpr_zenbot
- RIGHT , relay log: panel titled "Relay Log", one designed
  empty state: "No relays yet. Add TPR to a group and speak."
Log out sits small under the shape.
yields: the Battle Log shell, honest at zero.
:: ∎

## the auth function

▛//▞ server side, exact, no shortcuts
1. parse initData as querystring · extract hash
2. data_check_string = remaining fields k=v, sorted, joined
   by newline
3. secret = HMAC_SHA256(key="WebAppData",
   msg=TELEGRAM_BOT_TOKEN)
4. expected = hex HMAC_SHA256(key=secret,
   msg=data_check_string)
5. constant-time compare vs hash · mismatch = reject
6. reject if auth_date absent, older than 3600s, or future ·
   reject if no user field
7. success: upsert User by telegram_id · session · return who
yields: identity proven by signature, not by claim.
:: ∎
