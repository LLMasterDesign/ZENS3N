════════════════════════════════════════════════════════════
▛///▞ LAW :: First Principles
The build holds to every law here. Break one and the build is
wrong, no matter how good the rest looks.

▛/// Real Or Empty
Every value on screen is a real value, or an empty state that
says it is empty. No placeholder product, no sample sale, no
chart drawn from invented numbers. A screen of fake data is
worse than a blank one, because it lies about what exists.

▛/// Telegram Is Identity
The only way a person becomes known to TPR is Telegram's own
signature. No password field, no email capture, no Google or
Apple button, no signup form anywhere. Telegram already proved
who they are; TPR only checks that proof.

▛/// The Token Stays Secret
The bot token lives in Base44 project secrets, read only by the
server-side auth function. It is never printed, logged, embedded
in client code, or returned in a response. Same for raw initData.

▛/// The Login Is The Whole Scope
This piece builds the login and the empty shell behind it, and
nothing else. No relay logic, no routing, no settings, no
billing. When the login works and the shell renders, it is done.
:: ∎

Numbers are large and confident and carry the color; prose stays

yields :: a battle report, not a dashboard.

════════════════════════════════════════════════════════════
▛▞ The Door
This is the screen a person sees before they are logged in, and
it is the only way in. On load, the page reads
window.Telegram.WebApp.initData and POSTs it to the server
function auth. While that check runs, the screen shows one quiet
line, "checking signature", and nothing that spins or flashes.

If the page was opened outside Telegram, there is no initData to
read. In that case the screen shows one centered card reading
"TelePromptR opens from Telegram", with a single gold button
linking to https://t.me/tpr_zenbot, and nothing else at all.

yields :: a door only Telegram can open.
:: ∎

════════════════════════════════════════════════════════════
▛▞ The Shell
This is the first screen a logged-in person lands on. It is the
battle-log shell, and today it is empty and honest about being
empty. Three zones, the same bones as the baseline image.

The top bar holds two running totals, right-aligned: "relayed 0"
and "spent 0". These are true counts. They read zero today
because zero is the truth, not because the number is missing.

The left column is the shape of the session, as plain rows: the
person's name, their Telegram id with a copy button beside it
the way a Game ID has one, the time they signed in, and the bot
they are talking to, @tpr_zenbot. Log out sits small at the foot.

The right side is the Relay Log panel. It holds one designed
empty state: "No relays yet. Add TPR to a group and speak." No
fake cards, no grayed-out examples, no chart flatlined at zero.

yields :: the battle-log shell, honest at zero, ready to fill.
:: ∎

════════════════════════════════════════════════════════════
▛▞ The Check
This is the server function auth, the thing that makes the login
real. It verifies Telegram's signature over the initData, exactly
as Telegram specifies, with no shortcut taken.

    1  parse initData as a querystring, and pull out hash
    2  data_check_string = every remaining field as k=v, sorted
       by key, joined with a newline
    3  secret   = HMAC_SHA256("WebAppData", TELEGRAM_BOT_TOKEN)
    4  expected = hex HMAC_SHA256(secret, data_check_string)
    5  compare expected against hash in constant time; a mismatch
       is a rejection
    6  reject also if auth_date is missing, older than 3600
       seconds, or set in the future; reject if there is no user
    7  on success, upsert a User by telegram_id, start a session,
       and return who the person is

A rejection returns a plain reason and logs nothing sensitive.

yields :: identity proven by signature, never by claim.
:: ∎

════════════════════════════════════════════════════════════
▛▞ The Record
Login needs exactly one entity, the smallest table that can hold
a signed-in person. It is created here and nothing else is.

    User :: telegram_id (unique) · username · first_name ·
            last_seen

yields :: one row per real Telegram person, nothing more.
:: ∎
