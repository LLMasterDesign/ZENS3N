1. Source & ownership

Know exactly which folder is the real site. Every future change starts here.

  • Write down the canonical source folder.See SOURCE.md.

  • Record the build/serve command and required assets.
staging verified

2. Public deployment

Local `7120` and the Tailscale `/zensen/` ingress now return the canonical entry hash. Production VPS, public DNS, and managed-domain cutover remain open.

  • Choose managed static hosting or Sites before buying a VPS.
  • Deploy a saved, versioned build.
  • Confirm HTTPS, redirects, 404 handling, and rollback.
  • Connect the real domain and verify DNS.
SEO

3. Search readiness

Make the page understandable to search engines before asking them to rank it.

  • Give each page one accurate title and meta description.See SEO.md.
  • Add canonical URL, robots.txt, and sitemap.xml.
  • Remove noindex when the public launch is intentional.
  • Test mobile layout, links, speed, and structured data.
AEO

4. AI answer readiness

Give AI systems clean facts, definitions, and source signals they can safely reuse.

  • Write a one-sentence answer for what ZENSEN is.
  • Use semantic headings, labeled sections, and visible text.See AEO.md.
  • Add an Organization/WebSite JSON-LD block only for facts shown on-page.
  • Publish an author/about/contact source of truth.
security

5. 2FA & access

Protect admin actions separately from public viewing. Do not put secrets in HTML.

  • Decide what needs authentication: admin, dashboard, or all pages.See SECURITY-2FA.md.
  • Use an identity provider with passkeys/TOTP and recovery codes.
  • Keep sessions, secrets, and authorization server-side.
  • Test lockout, recovery, logout, and unauthorized access.
maintainability

6. Semantic map

Each page section gets a stable name, purpose, owner, and file boundary.

  • List sections and their stable IDs in SECTIONS.md.
  • Give every section one job and one acceptance test.
  • Change one section at a time and run the smoke checklist.
  • Keep a changelog before publishing.
operating rule

Do not break the whole page

Before editing, identify the section ID. Edit only that section or its named asset. After editing, check navigation, mobile layout, console errors, forms, SEO metadata, and the deployment preview. If a change crosses sections, document the dependency first.
