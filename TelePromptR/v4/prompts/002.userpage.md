> Build the page a TelePromptR user lands on after signing in with
> Telegram. TelePromptR is a shared Telegram gateway: ONE bot token
> serves many users, and each user connects THEIR OWN agents to it.
> The operator does not own anyone's agents or keys. Every section
> below is: heading, the aim in one line, the parts, then `yields`.
>
> Source of truth for this behavior is the owner's own routing spec
> (TPR Multi-Agent Routing Spec, ⧗ 2026-05-19): "Only TelePromptR
> talks to Telegram API. All agents publish envelopes to
> TelePromptR; TelePromptR resolves routing and emits to Telegram."

════════════════════════════════════════════════════════════
▛▞// LAW :: First Principles
The build holds to every law here, or it is wrong.

▛/// Real Or Empty
Every value on screen is real, or the field says it is empty. No
placeholder agent, no sample message count, no fake status dot. An
empty state that says "none yet" is honest; invented data is not.

▛/// Telegram Is Identity
A user is known only by Telegram's signed initData, verified server
side. No password, no email, no signup form anywhere.

▛/// The User Owns Their Swarm
Agents, keys and routes belong to the user who added them. The
operator never sees another user's key. A user sees only their own
agents, groups and topics — never anyone else's.

▛/// Keys Are Write-Only
An agent key is entered once and never displayed again. Show only
a masked tail (••••4f2a) and the date it was added. Nothing in the
UI, logs, or an API response ever returns a full key.

▛/// One Boundary
Only TelePromptR talks to Telegram. The page never calls the
Telegram API directly; it reads and writes through TPR alone.
:: ∎

════════════════════════════════════════════════════════════
▛▞// THE LOOK :: dark ledger, phone first
The page is read on a phone inside Telegram, so it is built for
one hand and a small screen.

    ink #EDF1F7 · dim #8B94A8 · gold #F2C14E

▛▞ Type And Motion
Large confident numbers, quiet gray prose. Gold marks only what
matters. Inputs are 16px so the phone never zooms. Things appear;

quiet word.

yields :: a control panel, not a marketing page.

▛▞// WHO :: the identity strip
The top of the page states who is signed in, so the user never

    name · @handle · telegram id (with a copy button)
    signed in (plain date and time, never a raw timestamp)

yields :: no doubt about whose page this is.
:: ∎

════════════════════════════════════════════════════════════
▛▞// MY AGENTS :: the swarm
The heart of the page: the agents this user has connected to the
gateway, and the one control that matters — which one answers.

▛▞ The List
One row per agent: name · a status dot (live · idle · denied) ·
the masked key tail · the scope it is allowed to speak in. A row
is tappable to open its detail.

▛▞ Add An Agent
A form with: agent name, its key (write-only, entered once), and
the scope it may speak in. On save the row appears with a live
dot. The key is never shown again.

▛▞ Which One Answers
Each agent row has a radio-style choice so the user picks the agent
that answers in the selected group or topic. Exactly one is active
per topic. Changing it takes effect immediately and shows a small
"routed → <agent>" confirmation.

▛▞ Empty State
"No agents yet. Add one and it can answer in your groups."

yields :: a user's own swarm, with routing they control.
:: ∎

════════════════════════════════════════════════════════════
▛▞// MY ROOMS :: groups and topics
Where the swarm speaks. A room is a Telegram group TPR was added
to; a topic is a thread inside it.

▛▞ The Tree
Group title · a joined/left state · beneath it each topic, and
for every topic the agent currently routed to it. A topic with no
agent reads "unrouted".

▛▞ Listen Only
Each topic has a listen-only toggle. Listen-only means the agent
ingests the topic silently and does not reply — per the owner's
CyberLobby plan, the default for a subscribed topic.

▛▞ Empty State
"TPR is in no groups yet. Add @tpr_zenbot to a Telegram group,
turn Topics on, and the group appears here."

yields :: the user sees exactly where their agents can speak.
:: ∎

════════════════════════════════════════════════════════════
▛▞// THE LOG :: proof it ran
Every routed message leaves a receipt, so the user can see the
gateway working instead of trusting it.

    newest first, one card per relayed message:
    who asked → which agent answered → the topic it landed in
    · ms · delivered ✓ or denied with its reason

A denied route names why it was denied. Totals sit at the top of
the page: routed · denied — real counts, zero when zero.

yields :: the gateway is legible, not a black box.
:: ∎

Every row carries `owner`. A query without an owner filter is a
bug: a user must never read another user's rows.

yields :: per-user isolation by construction.
