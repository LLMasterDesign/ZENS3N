3OX.Ai · 1n3ox.ai

Persistent AI agents, not disposable prompts.

3OX.Ai is model-agnostic infrastructure for running AI agents as durable systems: each agent lives in a self-contained cube with fixed identity, routing, policy, and lifecycle contracts, so you can swap models, move devices, and evolve capabilities without losing the substrate that keeps the agent coherent over time.

Architecture: the 5-6-7-7-2 lattice

The shape stays fixed so teams always know where to look. Contents evolve; topology does not.

5 · 5TRATA

Containment chain: CMD → Base → Station → Service → Agent.

6 · Cube Faces

Every .3ox/ has Spark, Brains, Rules, Toolkit, Links, Pulse for identity and execution.

7 · vec3 Kernel

Runtime directories: rc, lib, dev, var, bin, mem, proc.

7 · Service Modules

Arc, Pulse, Queue, Supervisor, Tape, Warden, Worker coordinate agents across cubes and devices.

2 · Anchors

_meta (identity/integrity) and _TRON (device runtime contracts).

5TRATA → L2 .3ox faces → L3 .vec3 kernel → 3OX service mesh → anchors

Get Started

  1. Create or clone an agent directory with a .3ox/ cube layout.
  2. Run ruby .3ox/Pulse/run.rb to boot the chain:
    • Reads sparkfile.md (identity)
    • Reads soul.md when present (purpose)
    • Loads brains.rs (persona rules)
    • Checks tools.yml and routes.json (capabilities + routing)
    • Validates limits.toml (constraints)
    • Appends first entry to 3ox.log
  3. Optional deployment flow: sync to VPS, merge TelePromptR config, restart runtime services.
  4. Optional Telegram onboarding: sign on teleprompter, create topic, and route messages by agent.

What is running today

  • Money.Bagz responds in Telegram.
  • TelePromptR routes inbound messages to the correct agent/topic.
  • speaker-mesh handles inference and streaming responses.
  • 3ox CLI + Vec3Boot provide build/boot tooling from the Rust workspace.
  • Deployment pipeline syncs agent cubes from build to runtime.
